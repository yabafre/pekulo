## Lessons applicable

- **Decimal coercion at Prisma → DTO boundary** (Scope: aped-arch, aped-dev — stories 0-6, 1-2, 2-1, 3-1, 5-1, 7-1, 7-3). Rule: `Number(decimal)` silently truncates above MAX_SAFE_INTEGER; coerce via `.toNumber()` (or the shared `decimalToNumber(row, default)` helper). Why: silent precision loss on monetary fields. How to apply: every `holdings.repository.ts` read that surfaces `quantity`, `unitPrice`, `fees`, `lastPrice` MUST run through `decimalToNumber` before returning to the service; AC will assert exact equality on a value > MAX_SAFE_INTEGER.
- **Elysia 1.4 type invariance** (Scope: aped-arch, aped-story, aped-dev — story 3-1 explicitly listed). Rule: the `Elysia` type is invariant; annotate boundaries with inference + `AnyElysia`. Why: explicit `Elysia` annotations break compilation at module composition. How to apply: zero bare `Elysia` annotations in `apps/api/src/modules/holdings/`; rely on type inference at the module factory boundary.
- **Zero `*.types.ts` inside `apps/api/src/modules/**`** (Scope: aped-arch, aped-dev, aped-review). Rule: every TS type lives in `@pekulo/types`(including internal API adapter interfaces). Why: prevents drift between API-internal types and the public domain model. How to apply:`Holding`, `HoldingLot`, `PriceQuote`, `PortfolioSnapshotFx`, derived types — all defined in `packages/types/src/`; the module folder only carries `<name>.schema.ts` for Zod-internal boundaries.
- **`pekuloColors` 1:1 mirror SSOT** (Scope: aped-dev, aped-arch, aped-review). Not applicable to 3-1 directly (API-only) but relevant for the downstream 3-4 UI work.
- **TR-strict palette — `$accent` reserved for ± monetary deltas** (Scope: aped-dev, aped-review). Not applicable to 3-1 directly but governs 3-3/3-4 UI surfaces consuming PnL.
- **`vitest run` exits 1 with no test files — add `--passWithNoTests`** (Scope: aped-dev). Why: blocks CI when a new module's test files are added incrementally. How to apply: ensure `apps/api/package.json` test script preserves `--passWithNoTests` and any new vitest workspace for holdings keeps the flag.
- **`bun --cwd <relative> run <script>` silently fails — use `--filter` or cd-then-run** (Scope: aped-dev, aped-story). How to apply: every command surfaced in the story file uses `bun --filter=api run …`, never `bun --cwd apps/api …`.
- **`bun test` ≠ `vitest run`** (Scope: aped-dev, aped-review). How to apply: CI must invoke the per-package `test` script for `apps/api` (which uses `bun test` for module-level tests per architecture); story TDD verbs must distinguish vitest (web) from bun test (api).
- **`AsyncLocalStorage.enterWith` correctness depends on Next.js per-request `ResourceContext` isolation** (Scope: aped-arch, aped-dev). How to apply: the 3-1 web-tier action wrappers MUST go through `apps/web/src/lib/orpc/request-context.ts` (do not invent a sibling context for holdings).
- **`@elysiajs/opentelemetry@1.4.0` rootSpan-export hooks do not fire in Elysia 1.4.4 + Bun** (Scope: aped-arch, aped-dev — every apps/api story that touches OTel). How to apply: in 3-1, do NOT rely on rootSpan-export hooks for tracing the resolveQuote chain — use explicit child spans from `apps/api/src/platform/observability/`.
