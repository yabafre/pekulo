## Architecture references

- Patterns to respect:
  - **Auth: Supabase Auth — email + password (brownfield, retained), session via SSR cookie (`@supabase/ssr` v0.10) on `apps/web`** (architecture L137). The Supabase JWT is forwarded as `Authorization: Bearer <jwt>` to `apps/api` on every oRPC call; `apps/api`'s `requireUserContext(request)` verifies it via `SUPABASE_JWT_SECRET` (L139, L605). TOTP MFA is reserved for the (b) ramp — out of 8-1 scope.
  - **`apps/web` direct Supabase queries are limited to the Supabase Auth API only** (L142) — login/signup/logout/recover talk to Supabase Auth via the anon key (`NEXT_PUBLIC_*`); all domain data reads/writes go through `apps/api` via oRPC. Do NOT add a domain DB read on the web side in this epic.
  - **`getClaims(token)` for server-side identity — never read `session.user.*`** (lesson 2026-06-01, below). `getSession()` is safe for the raw token; identity (`userId`/`email`) is derived from `getClaims(token)` (local JWKS verification). This is the load-bearing auth-flow pattern for 8-1's server surfaces.
  - **Auth gate = `apps/web/src/proxy.ts` middleware** (project-context L57, architecture L424): redirects unauthenticated users to the login route, redirects authenticated users away from `/(auth)/*`, exempts `/api`, `/_next`, `/v1/logos` (exact), and any path containing `.`. NFR-9's 401<100ms is the proxy's contract. 8-1 reaffirms / extends it for the recover path.
  - **Route group `(auth)`** holds `login`, `signup`, `callback`, `recover` (architecture L409, L527-530). Loading/Error matrix: **`login` + `signup` ship NO `loading.tsx`/`error.tsx`** (public, ❌/❌); **`callback` + `recover` ship BOTH** (✅/✅). Match this matrix exactly.
  - **oRPC `/rpc/v1/auth` contract sub-tree exists** (architecture L163, L388) and an `apps/api/src/modules/auth/` module slot is named (L437). Decide at the step-04 design gate whether 8-1 needs any `apps/api` auth procedure at all — most of the flow (signUp/signInWithPassword/signOut/resetPasswordForEmail) is Supabase-client-native on `apps/web` and may need **no** new oRPC method. Do not scaffold an empty module to "fill the slot".
  - **Hard web layering (ADR-0010, L544):** Component → Hook → `'use server'` `auth-actions.ts` → (Supabase client | oRPC client). `'use server'` files are grouped per feature (`auth-actions.ts` co-locates logout/refreshSession/… — architecture L345). `auth-actions.ts` must NOT be imported cross-feature (`no-cross-feature-action-import`, L546).
  - **Typed domain errors** extend `PekuloError`; `UnauthorizedError` already exists (L139, L186, L579). The Elysia error-mapper converts to oRPC 4xx (`code` + `message`). Any new auth error code is added to the mapper.
  - **Zustand never mirrors server state** (L549) — relevant to 8-2 (theme/lang client mirror) more than 8-1; carry it forward.

## Lessons applicable

- **Server-side Supabase identity uses `getClaims(token)`, never `session.user.*`** (2026-06-01; scope aped-dev/aped-arch). auth-js wraps `session.user` in `insecureUserWarningProxy` and emits "Using the user object from getSession() could be insecure" ONLY when you READ a `session.user.*` property — NOT on `getSession()` itself nor on `session.access_token`. Keep `getSession()` for the raw token (safe), derive `userId`/`email` from `getClaims(token)` (local JWKS — ES256 no network round-trip; HS256 legacy falls back to `getUser()`). **Directly binds 8-1** (every server-side auth read).
- **Elysia 1.4 `Elysia` type is invariant** — use type inference + `AnyElysia` at module boundaries, never annotate the concrete `Elysia` generic (2026-05-04; the lesson's scope list **names story 8-1**). Relevant only if 8-1 adds an `apps/api` auth route.
- **A web-tier `defineAction` returning a `{ ok: true } | { ok: false, code, message }` envelope MUST omit `output:`** (2026-05-20) — zapaction core runs `output.parse(result)` unconditionally; a success-only schema rejects the error envelope. Auth actions that return a typed failure (bad-credentials, weak-password, rate-limited) hit this exactly — omit `output:`, add the AC-level envelope runtime test.
- **`tsc` is NOT in the commit gate** (2026-06-01) — run `bun --filter='@pekulo/web' run typecheck` (+ `@pekulo/api` if touched) manually before each commit; a green stubbed unit suite is not evidence the flow works.
- **Cross-check any UI placement against `docs/ux-preview/src/App.tsx`** before implementing (2026-05-17) — the `SettingsScreen` is authoritative for the logout/account placement in Paramètres (8-1) and the theme/lang controls (8-2).
- **Mid-flight scope additions carry doc-debt paid in the same change** (2026-05-31 / 2026-06-05; scope aped-story/dev/review) — if 8-1 grows past its step-04 scope lock (e.g. adds MFA, email confirmation, or an `apps/api` auth module), supersede the scope note, record the decision in an ADR Consequences block, refresh the architecture driver line, write the lesson, and recompile this cache. Default to SPLITTING a new-subsystem expansion into a sibling story.
