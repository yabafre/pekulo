# Quick Spec: Unify monorepo on Bun 1.3.14 and remove Node build:ci divergence

**Date:** 2026-11-22
**Author:** Alex
**Type:** refactor
**Status:** in-progress

## What

Pin Bun to `1.3.14` across the root manifest, GitHub Actions CI setup, and API Dockerfile (matching Vercel's `bunVersion: "1.x"` runtime), switch `@pekulo/web`'s `start` script to `bun --bun next start`, and remove the Node-only `build:ci` script so CI runs the same `bun --bun next build` as Vercel.

## Why

CI (`1.3.13`) diverged from Vercel (`1.3.14`) and hit Bun's `Expected CommonJS module to have a function wrapper` bug during `next build`, forcing a Node-only `build:ci` workaround that broke CI/prod runtime parity.

## Acceptance Criteria

- [ ] `package.json`, `.github/actions/setup-bun/action.yml`, and `apps/api/Dockerfile` all pin Bun `1.3.14`.
- [ ] `apps/web/package.json` runs `dev`, `build`, and `start` via `bun --bun next ...` and no longer defines `build:ci`.
- [ ] `.github/workflows/pr.yml` builds `@pekulo/web` via `bun --filter=@pekulo/web run build` (Bun runtime).
- [ ] Local validation (`lint`, `format:check`, `typecheck`, `test-unit` / relevant checks) passes with zero regressions, and PR CI (including `axe-a11y` under Bun `1.3.14` and Vercel preview) passes green.

## Files to Change

- `package.json` — bump `packageManager` from `bun@1.3.13` to `bun@1.3.14`
- `.github/actions/setup-bun/action.yml` — bump `bun-version` (and description) from `1.3.13` to `1.3.14`
- `apps/api/Dockerfile` — bump base image from `oven/bun:1.3.13-slim` to `oven/bun:1.3.14-slim`
- `apps/web/package.json` — switch `start` to `bun --bun next start -p 3002` and remove `build:ci`
- `.github/workflows/pr.yml` — invoke `bun --filter=@pekulo/web run build` instead of `build:ci`

## Test Plan

- Push draft PR and verify GitHub Actions `pr.yml` — specifically `axe-a11y` building and starting `@pekulo/web` with Bun `1.3.14` — plus Vercel preview deployment.
