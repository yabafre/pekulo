## Architecture references

- Patterns to respect:
  - **Module shape** (architecture.md §Structure Mapping): every `apps/api` module is `<mod>.{module,routes,service,repository}.ts` + `<mod>.service.test.ts` + `<mod>.integration.test.ts`. `settings` already exists with this exact shape — 11-1 / 11-2 extend it rather than creating a new module.
  - **oRPC contract-first** (ADR-0009): a procedure exists in `packages/contracts/src/<mod>/<mod>.contract.ts` before any handler. `settingsContractV1` currently exposes `get` / `updateTheme` / `updateLang`; `exportData` (11-1) and `deleteAccount` (11-2) are additive to that object. Mount path `/rpc/v1/settings`.
  - **Component → Hook → Server Action** (ADR-0010, hard boundary): the web tier never calls oRPC from a component. `_components/*.tsx` → `_hooks/use-*.ts` → `_actions/*.ts` (`defineAction`) → oRPC client. `_appearance/` is the reference implementation of this triad on the settings page.
  - **Authorization** (architecture.md §Authentication & Security, ADR-0013): `apps/api` connects with the Supabase **service role, which bypasses RLS**. Primary enforcement is `requireUserContext()` + `where: { userId }` on every Prisma query + the `no-prisma-query-without-user-id` oxlint rule. An export that fans out over 21 tables must carry the `userId` guard on **every** one — this is the single highest-risk surface in the epic for a cross-tenant leak.
  - **RLS coverage automation** (architecture.md:142, :239, :638): `apps/api/scripts/rls-migration-audit.ts` (static migration-SQL parse, CI job `rls-audit`) + `apps/api/scripts/rls-audit.ts` (DB-backed probe, local/post-deploy only, hardcoded `EXPECTED_POLICY_COUNTS`).
  - **Repository test pattern** (architecture.md:619): every `*.repository.ts` ships ≥ 1 happy-path + 1 RLS-isolation test (call from another `userId` returns empty/404).
  - **Audit sister tables** (ADR-0001): `compass_history`, `account_balance_log`, `real_estate_valuations`, `llm_call_log`, `bridge_users` are append-only (INSERT + SELECT policies only). They are user data and belong in a portability export.
- ADRs in scope: `adr/0009-elysia-orpc-with-zapaction-bridge.md` (contract-first + bridge), `adr/0010-hooks-orchestration-boundary.md` (web-tier triad), `adr/0013-prisma-rls-defense-in-depth.md` (service-role bypass — the `where:{userId}` guard is the only tenant boundary on the api path), `adr/0001-audit-history-via-sister-tables.md` (append-only tables), `adr/0015-bank-aggregator-bridge-with-provider-abstraction.md` (Bridge tokens stay server-side; the vault columns are vestigial NULL), `adr/0012-prisma-7-schema-folder-prefixed-ids.md` (prefixed IDs appear verbatim in any export), `adr/0003-pwa-offline-cache-encrypted-indexeddb.md` (client at-rest posture).

## Project context (brownfield only)

- Existing patterns the epic must respect:
  - **The live user-scoped table set is 21 tables**, not the 7 of the brownfield snapshot and not the 17 quoted in the #48 audit comment (written 2026-05-29, before `dashboard_layout` and `user_pref` landed): `accounts`, `holdings`, `holding_lots`, `account_balance_log`, `transactions`, `kpis`, `monthly_tracking`, `monthly_records`, `hypotheses`, `compass_history`, `milestones`, `real_estate`, `real_estate_mortgage`, `real_estate_rental`, `real_estate_valuations`, `bank_connections`, `bridge_users`, `llm_call_log`, `llm_opt_in`, `user_pref`, `dashboard_layout`. `merchant_logo_cache` / `provider_logo_cache` are **global** caches with no `user_id` — out of scope for a per-user export.
  - ⚠️ **`dashboard_layout` is absent from `EXPECTED_POLICY_COUNTS` in `apps/api/scripts/rls-audit.ts`** (20 entries, 21 tables). Not a security hole — its migration `20260604172000_dashboard_layout` does enable RLS with 3 policies — but it means **`rls-audit.ts` cannot be used as the source of truth for "every user table"**. Derive the export's table list from the Prisma schema (models carrying `userId`), not from the audit script.
  - `user_pref` and `dashboard_layout` are singleton rows keyed by `user_id` as the PK (no separate `id`); every other user table has a prefixed `id` (ADR-0012).
  - ⚠️ **The `ON DELETE CASCADE` from `auth.users` is NOT universal — 4 of the 21 user tables carry no FK to `auth.users` at all.** Verified against `apps/api/prisma/migrations/**` on 2026-09-15 (`grep 'REFERENCES auth.users'`): 16 tables declare it (`kpis`, `monthly_tracking`, `hypotheses`, `transactions`, `accounts`, `holdings`, `holding_lots`, `bank_connections`, `bridge_users`, `llm_call_log`, `llm_opt_in`, `monthly_records`, `real_estate`, `real_estate_mortgage`, `real_estate_rental`, `real_estate_valuations`); `account_balance_log` has none but cascades indirectly through `accounts(id) ON DELETE CASCADE`; and **`compass_history`, `milestones`, `user_pref`, `dashboard_layout` have no FK on any path** — deleting the `auth.users` row leaves their rows orphaned. Three of those four migrations carry a comment asserting the opposite ("row removal happens only via cascade from auth.users (story 11-2)") — the comment is aspirational, the constraint was never written. This is the central correctness problem of 11-2: a deletion built on "the FK cascade handles it" silently fails GDPR erasure on 4 tables.
  - Every user-scoped table carries `user_id UUID NOT NULL` + `auth.uid() = user_id` policies (CRUD tables: the full quartet; audit sister tables: INSERT + SELECT only; `user_pref` / `dashboard_layout`: SELECT + INSERT + UPDATE, no DELETE — so an RLS-path delete of those two is impossible by policy, though the api's service role bypasses RLS entirely per ADR-0013).
  - RLS policy DDL is appended manually to Prisma migration SQL — Prisma does not introspect policies (ADR-0014).
  - Identity (email, password hash) lives in **Supabase Auth**, not Postgres — a complete portability export has to decide whether to include the auth-side identity fields (`docs/rgpd-readiness.md` data map lists them as an in-scope category).
  - Tests exist: vitest (`apps/web`, `packages/*`) + `bun test` (`apps/api`). The `project-context.md` "no tests" note is stale post-Epic 0 — that file is a 2026-05-03 snapshot and is stale on structure generally.
  - `bun --filter=@pekulo/api` / `--filter=@pekulo/web` (workspace name, never the folder name).
  - `docs/exports/` **does not exist yet** — `schema-v1.json` is created by 11-1.
