## Lessons applicable

- **Coerce Prisma `Decimal` via `.toNumber()`** at every Prisma→DTO boundary — `Number(decimal)` silently truncates above MAX_SAFE_INTEGER (2026-05-04; scope names stories 7-1, 7-3). Binds every term of the projection curve. The V1 tolerance budget assumes monetary values ≤ 1e7 (Alex scale); the 0-6 `decimalToNumber` header explicitly flags revisiting this "before the projection curve lands". Sanity: 60 000 € compounded 30 y @ 5 % + 1 000 €/mo annuity ≈ ~1.06 M € — comfortably within MAX_SAFE_INTEGER, so `.toNumber()` is safe; document the budget in the story.
- **Elysia 1.4 `Elysia` type is invariant** — use type inference + `AnyElysia` at module boundaries, never annotate the concrete `Elysia` generic (2026-05-04; scope names 7-3).
- **A web-tier `defineAction` returning a `{ ok: true } | { ok: false, code, message }` envelope MUST omit `output:`** — zapaction core runs `output.parse(result)` unconditionally and a success-only schema rejects the error envelope at the SA boundary (2026-05-20). The rule explicitly names "7-3 (hypothesis writes)" and makes a `output:` near a `try/catch` returning `{ ok: false }` a [BLOCKER] grep target. Positive precedent: `accounts-actions#deleteAccount`, `holdings-actions#createHolding`/`#recordLot`.
- **Registry-SSOT cache invalidation, no wall-clock promises** — every mutation hook declares `invalidateWithTags: [<feature>Tags.X()]`; `defineAction({ tags })` is server-only (drives Next `revalidateTag`, NOT client React Query); manual `queryClient.invalidateQueries` in a hook body is a review fail (R4/R12, 2026-05-24/25). Don't promise "<500 ms"/"instant" in AC text unless an optimistic `onMutate` path + perf test ship with it.
- **Adding a Prisma model/column is inseparable from generate+migrate** — `tsc` is NOT in the commit gate; after any schema change run `prisma:generate && bun --filter='@pekulo/api' run typecheck` (+ relevant `bun test`) as one step, then `migrate deploy` to actually create it; a green STUBBED unit suite is not evidence the write path works (2026-06-01, 2026-06-05). A NEW model also needs an `id-prefixes.config.ts` entry — but `Hypothesis` already exists and skips the extension, so a column add to `hypotheses` needs generate+migrate but NO new registration.
- **No `*.types.ts` inside `apps/api/src/modules/**`** — every TS type lives in `@pekulo/types`, including the `HypothesisProjection` curve type (2026-05-09; architecture L1170 already pre-names it).
- **Mid-flight scope additions carry doc-debt paid in the same change** — if 7-3 grows past its step-04 scope lock (e.g. into a new column/subsystem), supersede (don't delete) the scope note, record the realized decision in the owning ADR Consequences, refresh the architecture driver line, write the lesson, and recompile this cache (2026-05-31 / 2026-06-05; scope: aped-story/dev/review). Default to SPLITTING a new-subsystem expansion into sibling stories.
- **Cross-check any UI placement against `docs/ux-preview/src/App.tsx`** before implementing (2026-05-17) — relevant if 7-3 ships the parametres `hypothesis-form.tsx`; the `SettingsScreen` ("Hypothèse de projection") is authoritative.
- **New cap-view routes land under `(cap)/dashboard/<feature>/`**, never `(cap)/` directly, or they render without the CapShell (2026-05-27) — relevant to any 7-3/7-4 route.
- **Desktop bento cell-fill (`flex:1 + minHeight:0`) must be `$lg`-gated** or it collapses the mobile flat column to 0 px (2026-06-09, story 7-2) — relevant to the 7-4 Hypothèse card; carried here as an epic-7 lesson.
