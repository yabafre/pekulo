## Architecture references

- Patterns to respect:
  - **Module shape** (architecture.md §Module shape, ADR-0009): `apps/api/src/modules/<name>/` = `<name>.module.ts` (factory → `{ router, service }`) + `<name>.routes.ts` (oRPC handlers) + `<name>.service.ts` + `<name>.repository.ts` + tests. `createXxxModule(deps)` receives `{ prismaService }` and is wired in `apps/api/src/bootstrap/runtime-dependencies.ts`, then added to the `orpcRouter` literal in the same file. Contract lives first in `packages/contracts/src/advisory/advisory.contract.ts` + sibling `index.ts`, re-exported from `packages/contracts/src/index.ts` and appended to `pekuloContract`. Mount path: `/rpc/v1/advisory`.
  - **Cross-cutting guard shape** (`apps/api/src/platform/security/opt-in-guard.ts`, the model 12-1 must mirror): the guard takes an **injected reader interface** (`ThirdPartyOptInReader`) rather than importing a module, preserving one-way layering `platform → common`, never `platform → modules`. Service supplies the repository that structurally satisfies the reader. Tests live next to the guard.
  - **Authorization** (architecture.md §Authentication & Security, ADR-0013): `apps/api` connects with the Supabase **service role and bypasses RLS**. Primary enforcement is `where: { userId: ctx.userId }` on every Prisma query + the `no-prisma-query-without-user-id` oxlint rule. The advisory access lookup must therefore scope on `userId` explicitly; RLS is defense-in-depth for the anon path only.
  - **RLS DDL is hand-appended** to the Prisma migration (ADR-0014). The static `apps/api/scripts/rls-migration-audit.ts` CI gate (`db:rls-migration-audit`, job `rls-audit`) fails if a new public user-data table lacks `ENABLE ROW LEVEL SECURITY` + ≥ 2 policies. `apps/api/scripts/rls-audit.ts` holds `EXPECTED_POLICY_COUNTS` for the DB-backed probe (local/post-deploy).
  - **Prefixed IDs** (ADR-0012): every new Prisma model MUST be registered in `apps/api/src/database/id-prefixes.config.ts`; a `user_id`-PK table gets `null` (no synthetic id). The DMMF meta-test `id-prefixes.config.test.ts` enumerates models and fails the build otherwise.
  - **Enumeration guards** (stories 11-1 / 11-2): a new user-scoped model MUST be added to both `EXPORT_NODES` (`settings.export.ts`) and `DELETION_NODES` (`settings.deletion.ts`) — the set-equality guard tests fail by name otherwise. It must also reach `auth.users` via `ON DELETE CASCADE`, directly or through a parent, or the cascade-reachability gate fails.
  - **Typed errors** (`apps/api/src/common/errors/pekulo-error.ts`): every new code goes into both the `PekuloErrorCode` union and the `PEKULO_ERROR_CODES` set, then into `platform/http/error-mapper.ts`. `FORBIDDEN` (403) already exists and is the natural gate code. oRPC only surfaces a typed error if the contract declares it under `.errors({...})`.
  - **oRPC context**: `mountOrpc` verifies the JWT and injects `{ userId, email }`; handlers call a local `requireUserId(context.userId)` then the service. Tests use `bun test` on `apps/api`, `vitest` on web/packages.
- ADRs in scope: `adr/0016-private-internal-ai-advisory-surface.md` (the whole story), `adr/0013-prisma-rls-defense-in-depth.md` (where-clause + lint + RLS quartet), `adr/0009-elysia-orpc-with-zapaction-bridge.md` (contract-first, `/rpc/v1`), `adr/0012-prisma-7-schema-folder-prefixed-ids.md` (id registry), `adr/0014-prisma-migrations.md` (hand-written RLS DDL, forward-only), `adr/0008-llm-routing-server-audit-authority-async-attest.md` (only relevant to 12-3; do not touch the categorisation path in 12-1), `adr/0015-bank-aggregator-bridge-with-provider-abstraction.md` (encryption-at-rest reference for 12-3).

## Lessons applicable

- **2026-06-05 (Scope: aped-dev, aped-review)** — a new Prisma model is three inseparable steps: schema + migration, register in `id-prefixes.config.ts` (`null` for a `user_id` PK), and actually deploy the migration. Stubbed repository tests hide a missing prefix registration (runtime 500 on first write). → `AdvisoryAccess: null`; exercise a real create/upsert once.
- **2026-06-02 (Scope: aped-dev, aped-review)** — "no PII" justifies omitting RLS _policies_, never omitting RLS itself; every public table is anon-reachable via PostgREST. → `advisory_access` is user data, so it needs RLS enabled AND its per-row quartet.
- **2026-06-15 (Scope: aped-dev, aped-review)** — a self-gating oxlint rule can be silently inert; prove any relied-upon rule fires on a deliberately violating fixture. → do not claim the `no-prisma-query-without-user-id` rule protects the new repository without checking it flags a missing `userId`.
- **2026-06-01 (Scope: aped-dev)** — typecheck is a manual gate before every commit; `prisma:generate` then `typecheck` after any schema edit; a surprising diff line count means the edit clobbered something.
- **2026-05-30 (Scope: aped-arch, aped-dev, aped-review)** — a client-supplied enum persisted to trusted state must be pinned to the server-legitimate subset, not the full domain enum. → the `status` field of any access write must be `active | banned` only at the server boundary; a client must never be able to write `granted_by` / `granted_at`.
- **2026-05-27 (Scope: aped-arch, aped-dev, aped-review, aped-debug)** — find-or-create over a UNIQUE `(scope, key)` must catch P2002 and re-read. → `advisory_access` is keyed by `user_id`; any upsert/grant path must be race-safe or provably idempotent.
- **2026-05-31 (Scope: aped-story, aped-dev, aped-review)** — scope added after the design lock carries doc-debt in the same change (story, epic context, owning ADR, architecture driver line, lesson). → the ADR-0016 PRD/architecture annotations are still missing; 12-1 must at least not contradict them and should flag the gap.
- **2026-05-27 (Scope: aped-arch, aped-dev, aped-review)** — every new page route belongs under `(cap)/dashboard/*`. → no route in 12-1; 12-4 inherits this.
- **2026-05-19 (Scope: aped-story, aped-dev, aped-review)** — every command in the story uses the fully-qualified workspace name.
