# Project Context: Pekulo

> Brownfield snapshot generated by `aped-context` on 2026-05-03.
> Pekulo is a goal-based personal-finance app — Persona #1 is the user (Alex). Central verb: _"set a compass, everything aligns"_. See `docs/grill-summary.md` for the V1 product framing decided on 2026-05-03.

## Tech Stack

### Repository

- **Monorepo** — Bun workspaces + Turborepo (`turbo.json`, `bun.lock`, `packageManager: bun@1.3.13`)
- **Workspaces** — `apps/*`, `packages/*` (the `packages/*` glob currently resolves to a single `.gitkeep` placeholder; no shared packages yet)
- **Env** — single root `.env` / `.env.local` consumed by every script via the `dotenv -e .env -e .env.local --` prefix in root `package.json`

### `apps/web` — Next.js dashboard

- **Language** — TypeScript 5 (strict), ES2017 target, `moduleResolution: bundler`
- **Framework** — Next.js **16.2.4** (App Router, Turbopack dev, RSC) on React 19.2.4
- **Styling** — Tailwind v4 (PostCSS), `tailwind-merge`, `class-variance-authority`, `tw-animate-css` / `tailwindcss-animate`
- **UI primitives** — shadcn (`style: base-nova`, `iconLibrary: lucide`) layered on `@base-ui/react` v1.4
- **Forms** — `@tanstack/react-form` + `zod` v4
- **Data layer** — `@tanstack/react-query` + `@zapaction/core` + `@zapaction/query` (server actions defined via `defineAction`, paired with feature keys/tags in `src/lib/zapaction/keys.ts`)
- **Charts** — `recharts` rendered through the shadcn `ChartContainer`
- **Backend** — Supabase JS (`@supabase/ssr`, `@supabase/supabase-js`); SSR cookie-based session (see `src/lib/supabase/server.ts`, `src/lib/supabase/client.ts`)
- **Price providers** — `yahoo-finance2` (npm), plus three sibling services in `src/lib/services/` (`prices-service`, `boursorama`, `twelve-data`)
- **Lint** — `eslint-config-next` v16 (core-web-vitals + typescript) via `eslint.config.mjs`

### `apps/prices` — Python price microservice

- **Language** — Python ≥ 3.10
- **Framework** — FastAPI 0.115 + Uvicorn 0.33
- **Data** — `yfinance ≥0.2.55,<0.3` driven by an explicit `curl_cffi` Chrome session (the most recent commit `2420412` makes that wiring explicit — yfinance is NOT auto-aware of curl_cffi)
- **Validation** — Pydantic 2.10
- **Auth** — optional `Authorization: Bearer <PRICES_SERVICE_TOKEN>`
- **Deploy** — Docker (Dockerfile in `apps/prices/`), targeted at Dokploy on the user's VPS

### Database — Supabase Postgres

- Single SQL file at `apps/web/supabase-schema.sql` (~270 LOC), idempotent (`CREATE TABLE IF NOT EXISTS`, `DO $$ BEGIN … EXCEPTION WHEN duplicate_object`).
- **Tables** — `kpis`, `monthly_tracking`, `hypotheses`, `transactions`, `accounts`, `holdings`, `holding_lots`
- **Enums** — `transaction_type` (`inflow`/`outflow`), `account_type` (`livret`/`pea`/`cto`/`av`/`autre`), `holding_kind` (`etf`/`action`/`autre`), `lot_type` (`buy`/`sell`)
- **RLS** — enabled on every table; per-table `auth.uid() = user_id` policies for `SELECT/INSERT/UPDATE/DELETE`
- **Compass-relevant columns** — `hypotheses.objectif` (target capital) + `hypotheses.horizon_years` already encode the "compass" decided in the grill — no migration needed for V1.

### Test framework

- **None.** No unit, integration, or E2E framework is wired (no `vitest` / `jest` / `playwright` / `pytest` in either app's deps or scripts). The only quality gates today are `bun run lint` (eslint) and `bun run typecheck` (`tsc --noEmit`) on the web side, and nothing on the prices side. **Tests are a known gap** — flag this when downstream skills (e.g. `aped-qa`, `aped-dev`) need a target framework.

## Architecture

### Pattern

- **Monorepo: Turborepo task graph** (`dev`, `build`, `lint`, `check-types`) with per-app independence
- **`apps/web`: Next.js App Router with feature-folder organisation**
  - Routes in `src/app/<route>/page.tsx` co-located with route-private `_components/`
  - Domain logic split by responsibility: `src/lib/{actions,data,schemas,services,supabase,zapaction}` + thin pure modules at `src/lib/derive*.ts` (snapshot derivation, FX-adjusted portfolio, monthly aggregation, lot-based avg cost)
- **`apps/prices`: Single-file FastAPI service** (`main.py`, ~6 KB) — health probe + `/quote` + `/quotes` (batch). Stateless, ~120 MB idle.
- **Auth boundary** — `src/proxy.ts` is the Supabase-aware Next.js middleware: redirects unauthenticated users to `/auth/login`, redirects authenticated users away from `/auth/*`, exempts `/api`, `/_next`, and any path containing `.`.

### Entry points

| Layer           | Entry                                                                            |
| --------------- | -------------------------------------------------------------------------------- |
| Web dashboard   | `apps/web/src/app/layout.tsx` → `apps/web/src/app/page.tsx`                      |
| Auth flow       | `apps/web/src/app/auth/{login,signup,callback}`                                  |
| Dashboard pages | `apps/web/src/app/dashboard/{page,parametres,mensuel,transactions,portefeuille}` |
| API             | `apps/web/src/app/api/dashboard/route.ts`                                        |
| Prices service  | `apps/prices/main.py` (`uvicorn main:app`)                                       |
| Edge auth gate  | `apps/web/src/proxy.ts`                                                          |

### Key modules

- **`src/lib/zapaction/context.ts`** — `setActionContext` registers a single async builder that resolves `{ supabase, userId, email }` per request and throws `UNAUTHORIZED` on missing user; every server action receives this `ActionContext`.
- **`src/lib/zapaction/keys.ts`** — feature-scoped query keys + invalidation tags; the `setTagRegistry` block at the bottom is the single source of truth for cache invalidation graphs (e.g. portfolio snapshot is invalidated by accounts and holdings tags).
- **`src/lib/services/prices.ts`** — orchestrates the **4-tier price fallback chain** (`prices-service` → `yahoo-finance2` → Boursorama scraping → Twelve Data) with a 60 s in-memory cache keyed by `ticker|kind|currency`; returns a `PriceQuote` with the winning `provider` field, or throws a composite `PriceError` listing every attempt.
- **`src/lib/derive-portfolio-fx.ts`** — pure function that combines accounts + holdings + FX rates into a `PortfolioSnapshotFx`; FX rates fetched best-effort via `getRates`, fallback 1:1.
- **`src/lib/derive-lots.ts`** — derives weighted-average `quantity` and `avg_cost` per holding from its lots; back-compat: a holding with zero lots remains in manual entry mode.

## Conventions

### Naming

- **Files** — kebab-case (`portfolio-view.tsx`, `derive-portfolio-fx.ts`, `holding-form.tsx`)
- **Route-private folders** — `_components/` prefixed with underscore (Next.js convention to opt out of routing)
- **Domain types** — PascalCase TS interfaces in `src/lib/types.ts` (`Account`, `Holding`, `MonthlyRecord`, `KpiData`)
- **Domain literals** — `as const` arrays in schema files (`ACCOUNT_TYPES`, `HOLDING_KINDS`, `CURRENCIES`) paired with inferred unions and `RECORD<T, string>` label maps
- **Database** — `snake_case` columns (`user_id`, `cash_balance`, `last_price_at`, `occurred_on`); row-to-domain mappers (`accountRow`, `holdingRow`) live next to each action / data module and convert in both directions
- **Server actions** — exported `defineAction<Input, Output, ActionContext>({ name: "verbNoun", input: zodSchema, handler })`; `name` is the wire identifier and matches the export

### Code organisation

- **Domain-by-feature inside `src/lib`** — every domain (`hypotheses`, `monthly`, `transactions`, `portfolio`, `holding-lots`) has parallel files in `actions/`, `data/`, `schemas/` (and feature keys/tags in `zapaction/keys.ts`)
- **Server-only enforcement** — `import "server-only"` at the top of every `data/*` module and `services/prices.ts` (forces a build error if a client component imports them)
- **Mutations vs reads** — writes go through `actions/*` (server actions, revalidate paths/tags via `revalidatePath` + zapaction tags), reads go through `data/*` (server-side Supabase fetch returning typed domain objects)

### Error handling

- **Server actions** — throw raw `Error` (or domain errors like `PriceError`, `YahooError`); zapaction surfaces them to the client. The action context throws `UNAUTHORIZED` on missing session.
- **Data readers (`src/lib/data/*`)** — wrapped in `try/catch` and return empty arrays / safe fallbacks on failure (graceful degradation pattern, e.g. `readAccounts` returns `[]` if Supabase errors)
- **Price providers** — each provider exports its own typed error class (`YahooError`, `BoursoramaError`, `TwelveDataError`, `PricesServiceError`) and the orchestrator collects every reason into a `PriceError.attempts` array
- **FX** — best-effort, falls back to 1:1 silently inside `derive-portfolio-fx.ts`

### Logging

- No structured logger. Server-side: ad-hoc `console.error`. Prices service: `print(..., file=sys.stderr, flush=True)` with a `[prices-service]` prefix.

### Config / secrets

- Single root `.env` / `.env.local`, documented in `.env.example`; loaded by every script via `dotenv -c -e .env -e .env.local --` (so `NEXT_PUBLIC_*` reaches Next, and `PRICES_SERVICE_TOKEN` reaches Python).
- All `NEXT_PUBLIC_*` vars are surface keys (Supabase URL + anon key); the service-role key is never read on the web side (RLS + anon is the only path).

### Hidden constraints / non-obvious rules

- **Next.js 16 is not the Next.js training data describes.** `apps/web/AGENTS.md` is explicit about this — App Router APIs, file structure and conventions have moved. Always read `apps/web/node_modules/next/dist/docs/` (or the relevant Next 16 doc) before generating Next-specific code.
- **`yfinance` does NOT auto-detect `curl_cffi`.** `apps/prices/main.py` builds an explicit `curl_cffi.requests.Session(impersonate="chrome")` and passes it to every `yf.Ticker(...)`. Do not "simplify" by removing the session — Yahoo will rate-limit any VPS-IP request that uses the stdlib session.
- **Server-only modules are enforced by import**, not by directory. Anything in `src/lib/data/*` and `src/lib/services/prices.ts` starts with `import "server-only"`. Keep that line on any new server-side module to fail fast on accidental client imports.
- **Cache invalidation is graph-driven via `setTagRegistry`** in `src/lib/zapaction/keys.ts`. When you add a feature, register both keys and tags, then wire the invalidation edges in the `setTagRegistry({...})` block — actions trigger tags, the registry maps tags back to keys.
- **No tests exist.** Any TDD-style work needs to install a framework first (vitest is the natural fit alongside Next 16 + React 19). Treat the absence as a deliberate gap, not an oversight to silently fill.
- **Single-user-by-RLS, multi-user-ready.** Every table has `user_id` + per-row RLS already; new tables MUST follow the same pattern (`user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE` + four `auth.uid() = user_id` policies). The grill marked Supabase RLS posture + at-rest encryption as **deferred** — load-bearing the moment the (b) public ramp triggers.
- **Compass schema already exists.** Don't re-invent `objectif` / `horizon` columns — extend `hypotheses` (or add a sibling `milestones` table) rather than replacing.
- **Project type is `brownfield`**, but the grill outcome will graft fresh modules (Tamagui DS in `packages/ui`, Expo RN in `apps/mobile`, LLM endpoint reusing the Dokploy VPS). The next `aped-context` re-run after those land will likely flip the type to `hybrid`.
