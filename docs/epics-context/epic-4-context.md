## Lessons applicable

- **L1 — Zero `*.types.ts` inside `apps/api/src/modules/**`\*\* (Scope: aped-arch, aped-dev, aped-review).
  - Rule: every TS type lives in `@pekulo/types`. Internal adapter interfaces co-located inside `*.module.ts` / `*.service.ts` / `*.repository.ts` are allowed (precedent: story 3-2 `holdings.cache.ts` co-locates `CacheEntry`).
  - Why: prevents drift between API-internal types and the public domain model.
  - How to apply: `RealEstate`, `RealEstateMortgage`, `RealEstateRental`, `RealEstateValuation`, `RealEstateId`, `RealEstateMortgageId`, etc. all live in `@pekulo/types/src/index.ts` as `z.infer` re-exports from `@pekulo/validators/src/realestate.ts` + branded IDs. **Never create `apps/api/src/modules/realestate/realestate.types.ts`.**
- **L8 — Elysia 1.4 `Elysia` type is invariant** (Scope: aped-arch, aped-dev — story 4-1 explicitly listed in the lessons.md scope list at L233).
  - Rule: never annotate variables/parameters as bare `Elysia`. Rely on inference at the module factory boundary or use `AnyElysia` for cross-cutting utilities.
  - Why: explicit `Elysia` annotations break compilation when the chain accumulates routes / lifecycle hooks.
  - How to apply: `createRealestateModule(deps)` returns `RealestateModule = { service, router: ReturnType<typeof createRealestateRouter> }`. AC must include a grep guard: `grep -rEn ':\s*Elysia\b|as\s+Elysia\b|<Elysia\b' apps/api/src/modules/realestate | wc -l` returns `0`.
- **L24 — `Number(decimal)` silently truncates above MAX_SAFE_INTEGER** (Scope: aped-arch, aped-dev — story 4-1 explicitly listed in the lessons.md scope list at L233).
  - Rule: coerce via `.toNumber()` (or the shared `decimalToNumber(value, fallback)` helper at `apps/api/src/common/derive/decimal-to-number.ts`).
  - Why: silent precision loss on monetary fields at large valuations (a Persona-#1 property valuation will stay well under MAX_SAFE_INTEGER, but the rule is invariant).
  - How to apply: every `realestate.repository.ts` boundary that surfaces `currentValuation`, `outstandingPrincipal`, `monthlyPayment`, `annualRate`, `monthlyRent`, `monthlyCharges` runs through `decimalToNumber(row.X, 0)`. AC asserts `grep -rn 'Number(.*Decimal' apps/api/src/modules/realestate | wc -l` returns `0`.
- **2026-05-19 — `bun --filter='@pekulo/api'` (NOT `bun --filter=api`)** (Scope: aped-story, aped-dev, aped-review).
  - Rule: workspace `--filter` MUST use the full `package.json#name`. Pekulo workspaces are namespaced `@pekulo/*`. **`bun --filter=api …` exits `No packages matched the filter`.**
  - How to apply: every command in the story file uses `bun --filter='@pekulo/api' run …` (quoted to prevent shell glob expansion). Fan-out across workspaces: `bun --filter='@pekulo/*' run <script>`.
- **2026-05-07 — `bun test` ≠ `vitest run`** (Scope: aped-dev, aped-review).
  - Rule: `apps/api`'s `test` script runs `bun test` (Bun's native runner). All new `*.test.ts` under `apps/api/src/**` use `import { describe, expect, mock, test } from "bun:test"` — never vitest globals.
- **2026-05-05 — `bun --cwd <relative> run <script>` silently fails** (Scope: aped-dev, aped-story).
  - Rule: use `bun --filter='@pekulo/api' run <script>` or `cd apps/api && bun run <script>`. Never `bun --cwd apps/api run …` in story commands.
- **2026-05-04 — Manual SQL migrations preferred over `prisma migrate dev` on this repo** (Scope: aped-arch, aped-dev — codified by stories 1-1, 2-1, 2-2, 3-1 deviations).
  - Rule: write the migration SQL by hand under `apps/api/prisma/migrations/<timestamp>_<name>/migration.sql`, then apply via `bun --filter='@pekulo/api' run prisma:migrate:deploy` (which sets `DATABASE_URL=$DIRECT_URL` per `prisma.config.ts`).
  - Why: `prisma migrate dev` hangs against the Supabase pooler. The deploy path uses the direct connection and works reliably.

  - How to apply: 4-1 is API-only — the Pre-Implementation Checklist must confirm no UI claim is embedded. UI surfaces belong to 4-3.
- **2026-05-20 — `defineAction` discriminated-union envelope returns MUST omit `output:`** (Scope: forward-pointer to 4-3 / future write-path SAs).
  - Not directly applicable to 4-1 (no web-tier SA in this story), but the contract surface defined here must allow envelope-shaped returns from any future SA wrapper that propagates `REALESTATE_NOT_FOUND` / `MORTGAGE_ALREADY_ATTACHED` / `RENTAL_ALREADY_ATTACHED` codes.
