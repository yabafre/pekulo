## Architecture references

- Patterns to respect:
  - **Module shape (architecture Phase 3 Code Structure):** extend the existing `apps/api/src/modules/transactions/{transactions.service,transactions.repository,transactions.routes,transactions.module}.ts` rather than introducing a new module. Add `importCsv` to the service, `bulkCreate` (or a `createMany` wrapper) to the repository, and `importCsv` to the routes. **Zero `*.types.ts`** (L1 invariant — every domain type in `@pekulo/types`).
  - **Folder-by-domain in packages (R11 — PR #86 audit codification):** the transactions slice already follows the post-audit layout. 5-2 only extends existing files:
    - `packages/validators/src/transactions/transactions.schemas.ts` (extends with `csvRowSchema`, `csvImportInputSchema`, `csvImportOutputSchema`).
    - `packages/contracts/src/transactions/transactions.contract.ts` (extends with a 6th procedure `importCsv` — sub-tree-versioned, no major bump).
    - `packages/types/src/transaction/transaction.types.ts` (re-exports the new inferred types).
  - **Layer separation (ADR-0010):** Component → Hook → Server Action → oRPC client → Elysia handler → service → repository → Prisma. CSV parsing happens entirely server-side in the service layer (NEVER trust the client-parsed preview — the form sends raw CSV text + parsed rows, server re-parses and validates).
  - **`@pekulo/zod` SOLE zod entry point (R1):** `from "@pekulo/zod"`, never `from "zod"`. Already applied in `transactions.schemas.ts`; preserve when extending.
  - **Defense in depth (ADR-0013):** every Prisma write in the bulk path carries explicit `where: { userId }` or stamps `userId` on every row. The cross-aggregate `accountId` probe (added in 5-1 as `AccountOwnershipProbe`) MUST be re-used by the CSV importer — every CSV row references an account by `account-label`, the server resolves label → `accountId` per user, then probes ownership before any insert. Lint rule `pekulo/no-prisma-query-without-user-id` blocks omissions.
  - **Atomic persistence (AC-2 in epics):** "When I confirm a clean preview, all valid rows persist atomically." Implementation: wrap the bulk insert in `prisma.$transaction` (interactive tx). Either all rows commit or none. On any row failure, the entire batch rolls back.
  - **Prefixed IDs (ADR-0012):** `Transaction → "tx"` already registered (5-1). The prefixed-ids extension injects `tx_<base62>` on every insert — including `createMany`-style branches. Verify the extension fires on `createMany` (it does for the `$transaction([...])` batch form; if `createMany` itself bypasses extensions, use per-row `create` inside `$transaction` — see Decisions deferred).
  - **Decimal → number boundary (L24):** `amount` is `@db.Decimal`. CSV parses string → number → `Prisma.Decimal` at insert; reuse `decimalToNumber()` from `apps/api/src/common/derive/decimal-to-number.ts` at every read-back DTO step.
  - **`Elysia` type is invariant (L8):** never annotate variables/parameters as bare `Elysia`. Inferred return types on the router factory.
  - **oRPC routing convention:** kebab-case, resource-oriented, plural. Non-CRUD action uses an explicit verb suffix: `/rpc/v1/transactions/import-csv` (procedure name `importCsv`). Sub-tree-versioned at `/rpc/v1/transactions` (no major bump for additive procedures).

The latter is server-only and does not preserve across the `"use server"` boundary.
  - **Error envelope discipline (lessons.md 2026-05-20):** the `importCsv` server action returns `{ ok: true; persisted: N } | { ok: false; code; message; rowErrors?: Array<{row: N, message: string}> }`. The `defineAction({ output: ... })` slot MUST be omitted — zapaction core runs `output.parse(result)` unconditionally and rejects the error branch. Positive precedents: `parametres/_actions/accounts-actions.ts#deleteAccount`, `portefeuille/_actions/holdings-actions.ts#{createHolding,recordLot}`, `dashboard/transactions/_actions/transactions-actions.ts#{createTransaction,updateTransaction,deleteTransaction}` (5-1).
  - **Hydration guard (R13 candidate — 2026-05-24 lesson):** every web-tier client component branching on `useActionQuery.isLoading` MUST gate the loading branch on a hydration flag (`isHydrated && isLoading`). Applies to the CSV preview table if it re-uses `useTransactions` to show "X new rows will land in Récentes".
  - **Tamagui CSS regen guard (2026-05-24 lesson):** any new `Pekulo*` primitive or variant introduced for the CSV preview UI MUST regenerate `packages/ui/public/tamagui.generated.css` (`bun run generate:tamagui-css`) and commit the diff in the SAME PR.
